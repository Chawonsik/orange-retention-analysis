# 귤 직거래 리텐션 분석 (Orange Retention Analysis)

가족이 4년째 판매하는 귤 직거래 주문 기록(2022–2025)을 BigQuery SQL로 분석. 지인 판매·시즌 상품 사업에서 리텐션을 축으로 세그먼트 기반 CRM 액션 매트릭스까지 설계함.

**역할**: 개인 프로젝트, 문제 정의부터 CRM 설계까지

**분석 결과 및 CRM 설계 · [슬라이드 6페이지 (PDF)](slides/deck-linear.pdf)**

## 데이터

원본은 4개년 손 엑셀. 연도당 시트 5개(판매자 3명 + 선물 + 택배비) 중 판매 시트 3개만 사용. 익명화 후 최종 3,981건 주문, 2,117명 고객. 데이터는 [`data/orders_anonymized.csv`](data/orders_anonymized.csv).

| 컬럼 | 설명 |
|---|---|
| season | 시즌(연도) |
| order_date / ship_date | 주문일 / 발송일 |
| seller | 판매한 가족 구성원 (익명화된 A/B/C) |
| customer_id | 익명 고객 ID |
| sido / sigungu | 배송지 시도/시군구 |
| qty_10kg / qty_5kg | 10kg/5kg 박스 수량 |
| product | 품명 |
| memo | 배송 관련 메모 |

**정제 시 발견**
- '박스 수량'(10kg) / '운임'(실제 5kg 박스 수) — 컬럼명·용도 불일치
- '받는 고객 핸드폰 번호' 칸은 전화번호가 아닌 배송 메모. 실제 연락처는 '받는 고객 전화번호'
- 소계 행 406건과 고객 정보 없이 품명·수량만 남은 복사 잔여물 1,370건 → 제거

**정제 처리**
- 고객 식별 키는 전화번호 사용 (이름은 구매자·부모님·회사명 혼재)
- 발송일 결측(3.9%만 채워짐)은 직전 값으로 채움. 주문일보다 발송일이 빠른 케이스 없음 확인 후 적용

**익명화**: 이름·전화번호·상세주소 제거. 판매자 익명 코드(seller_A/B/C)와 시도/시군구만 남김.

## 가설 및 핵심 결과

세 가설을 build-up 순서로 검증. 자세한 분석 흐름과 CRM 설계는 [슬라이드](slides/deck-linear.pdf) 참고.

| 가설 | 결과 | 강도 |
|---|---|---|
| **H1** 재구매 시 수량 확대는 리텐션 신호다 | keep_single 53.0% / expand_to_multi 59.3% (+6.3%p) | 방향은 맞으나 표본 54명, 격차 작음 → 약함 |
| **H2** 판매자별 재구매율 차이는 판매자보다 고객군 특성 | 원본으로는 seller_B 우세. 원본이 코호트 구성으로 왜곡될 가능성 → 세그먼트 통제 접근. 통제 후 방향이 코호트마다 갈림 (2024 multi에서 A가 B를 22.9%p 앞섬) | 부분 지지. 판매자 자체 요인은 단정 어려움 |
| **H3** 누적 시즌 수가 다음 시즌 재구매를 예측한다 | 신규 23.8% / 2시즌 63.0% / 3시즌 78.8% | 신규 대비 3.3배, 강함 |

→ CRM 지렛대는 H3 기반 세그먼트(**충성 263명 / 재구매 299명 / 신규 1,555명**)에 시즌 사이클 액션 매트릭스 매핑. 세그먼트 정의와 흉년·풍년 시나리오별 액션은 [슬라이드](slides/deck-linear.pdf) 5–6페이지.

## 쿼리

가설 순서대로 4개.

- [`01_retention_by_size_change.sql`](sql/01_retention_by_size_change.sql): H1 두 번째 시즌 수량 변화와 이후 재구매율
- [`02_customer_profile_by_seller.sql`](sql/02_customer_profile_by_seller.sql): H2 판매자별 고객군 프로필
- [`03_repurchase_by_seller_segment.sql`](sql/03_repurchase_by_seller_segment.sql): H2 세그먼트 통제 후 판매자별 재구매율
- [`04_retention_by_season_count.sql`](sql/04_retention_by_season_count.sql): H3 누적 시즌 수별 다음 시즌 재구매율

**원칙**
- 시즌 필터는 원본 행을 미리 지우지 않고 계산 후 HAVING/WHERE로 결과를 걸러냄 (시즌 삭제 시 계산 왜곡 방지)
- 고객마다 여러 값이 나올 수 있는 컬럼(판매자 등)은 `MAX(CASE WHEN season = first_season THEN seller END)`로 첫 구매 시점 값을 대표값으로 처리 (여러 판매자에게 산 고객 38명 확인 후 적용)
- 매 쿼리마다 합계 검증 별도 실행 (세그먼트별 고객 합 = 코호트 전체, 조인 뒤 행 수 = (고객, 시즌) 조합)

## 배움

- 원본 지표만 보고 판매자 요인으로 단정할 뻔한 지점 → 세그먼트 통제로 원인 층위 분리 필요성 확인
- 흔한 마케팅 상식(수량 확대 = 관여도)이 이 사업에선 강도 얕음 → 상식도 사업별 검증 필수
- 상관관계 강한 신호(H3)에도 자연 패턴 포함 가능 → 순수 개입 효과는 다음 시즌 실험으로만 분리 가능

## 한계

- H1 확대 그룹 표본 54명으로 작음 → 시즌 누적 후 재검증 필요
- H2 세그먼트 통제 후에도 남는 판매자 간 차이의 원인(사전 커뮤니케이션·관계 밀도)은 이 데이터만으로 좁힐 수 없음
- H3 격차는 상관관계지 인과 아님. CRM 개입 순수 효과는 다음 시즌 실적용 후 세그먼트별 변화로 확인 필요
- seller_C 표본 75명으로 판매자 비교에서 조심스러운 해석 필요
- 전화번호가 없는 소수 고객은 이름·지역으로 식별 → 동명이인 오차 가능

## 사용 기술

BigQuery, SQL. 정제·익명화는 AI 활용.
